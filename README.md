# لوحة ميكائيل

لوحة تحكّم بتدير كذا حساب مع بعض: سفر جماعي لنفس المنطقة، ترقية المهارات،
والمهام اليومية — وكل حساب ليه البروكسي الخاص بيه.

---

## إيه اللي جوه

ملفين بس:

```
app.py             كل حاجة — السيرفر والمحرّك والتصميم والواجهة
requirements.txt   المكتبات
```

جوه `app.py` تمن أقسام معلّمة بعناوين، دوّر على الرقم عشان توصل بسرعة:

```
[١] الإعدادات          كل القيم القابلة للتغيير
[٢] قاعدة البيانات      الاتصال والجداول
[٣] التعامل مع اللعبة    نداءات الـ API
[٤] محرّك المهام        الطابور والتنفيذ وإعادة المحاولة
[٥] التصميم والواجهة    الـ CSS والـ JS
[٦] صفحات HTML
[٧] المسارات
[٨] الإقلاع
```

لما تحدّث حاجة، بترفع `app.py` بس على GitHub و Render بينشر لوحده.

**فكرة المحرّك:** أي أمر بتضغطه مبيتنفذش على طول — بيتحوّل لمهمة في جدول `tasks`
بموعد. ده معناه إن الأوامر الجماعية بتتوزّع على وقت بدل ما كل الحسابات تعمل نفس
الحركة في نفس الثانية، ولو السيرفر اتقفل المهام بتفضل مستنية وتتنفذ لما يرجع.

---

## ١. قاعدة البيانات — Supabase

1. اعمل مشروع جديد على [supabase.com](https://supabase.com).
2. من **Project Settings ← Database ← Connection string** اختار تبويب **Session pooler**.
3. انسخ الرابط، هيبقى شكله كده:
   ```
   postgresql://postgres.abcdefgh:PASSWORD@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```
4. غيّر `PASSWORD` بكلمة سر القاعدة بتاعتك.

> **مهم جداً:** لازم تاخد رابط الـ **Session pooler** مش الـ **Direct connection**.
> الاتصال المباشر بقى IPv6 بس، و Render المجاني مبيدعمش IPv6 — فالبوت مش هيقدر
> يوصل للقاعدة خالص ولو الرابط شكله سليم.

الجداول بتتعمل لوحدها أول ما البوت يشتغل. مش محتاج تعمل أي حاجة في Supabase.

## ٣. النشر على Render

1. **New ← Web Service** واربطه بالريبو.
2. الإعدادات:
   - Runtime: `Python 3`
   - Build: `pip install -r requirements.txt`
   - Start: `gunicorn app:app --workers 1 --threads 8 --timeout 120 --bind 0.0.0.0:$PORT`
   - Plan: `Free`

> خلّي `--workers 1` زي ما هي. لو زوّدتها، النبضة الداخلية هتشتغل أكتر من مرة
> في نفس الوقت وكل حساب هيبعت أوامره مكرّرة.

3. من **Environment** ضيف:

| المتغيّر | القيمة |
|---|---|
| `DATABASE_URL` | رابط الـ Session pooler من الخطوة الأولى |
| `OWNER_USER` | اسم الدخول للوحة |
| `OWNER_PASS` | كلمة سر قوية |
| `SECRET_KEY` | نص عشوائي طويل |
| `CRON_SECRET` | نص عشوائي تاني |

تولّد المفاتيح العشوائية كده:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

## ٤. الخطوة اللي من غيرها البوت مش هيشتغل

الخطة المجانية على Render بتنيّم الخدمة بعد ١٥ دقيقة من غير زيارات، وساعتها
النبضة الداخلية بتقف والمهام مبتتنفذش. الحل إن حاجة برّانية تنده على السيرفر
كل شوية.

1. افتح [cron-job.org](https://cron-job.org) واعمل حساب مجاني.
2. اعمل Cron Job جديد:
   - **URL:** `https://<اسم-خدمتك>.onrender.com/cron/tick?key=<CRON_SECRET>`
   - **كل:** ٥ دقايق
   - **Timeout:** ٦٠ ثانية

الطلب ده بيصحّي السيرفر وبينفّذ المهام المستحقة في نفس الوقت.

> أول طلب بعد نوم طويل ممكن ياخد نص دقيقة أو ياخد Timeout — عادي، السيرفر بيكون
> بيقوم. الطلب اللي بعده هيعدّي عادي.

## ٦. الاستخدام

**إضافة حساب** — اضغط `+ حساب`، اكتب اسم تعرفه بيه والمجموعة والتوكن.
التوكن بتجيبه من متصفحك وانت داخل باللعبة: `F12 ← Application ← Local Storage`،
دوّر على المفتاح اللي فيه التوكن وانسخ قيمته.

**المجموعات** — الحسابات اللي في نفس المجموعة بتتحرّك مع بعض. اختار المجموعة من
القايمة فوق، دوس `اختيار الكل`، وبعدين `سفر جماعي`.

**السفر الجماعي** — اختار المنطقة، وسيب خيار التوزيع الزمني شغّال. الحسابات
هتسافر واحد ورا التاني على فترة بدل ما يتحركوا كلهم في نفس اللحظة.

**البروكسي** — خانة واحدة بس. الصق البيانات زي ما هي:
`عنوان:منفذ:يوزر:باسورد` (أو `عنوان:منفذ` بس لو مفيش يوزر). البوت بيفكّها لوحده.
اضغط `اختبار الاتصال` بعد الحفظ عشان تتأكد إنه شغّال.

**الدول والسفر** — زرار `الدول والسفر` بيفتح قايمة كل الدول، كل دولة جنبها
`طلب فيزا` و`طلب إقامة` يطبّقوا على الحسابات المختارة، ودوس على اسم الدولة
تشوف مناطقها وتسافر لأي واحدة فيهم مباشرة.

> **ملحوظة عن الإقامة:** مسار طلب الإقامة (`/api/residencies/apply`) مبني على
> قياس مسار الفيزا لأننا ملقيناش الطلب الحقيقي وقت البناء. لو رجّع خطأ "مسار
> غلط"، افتح اللعبة في المتصفح، دوس F12 ← Network، اعمل طلب إقامة يدوي، وشوف
> اسم الـ request بالظبط — وابعته عشان يتظبط في سطر واحد بس في الكود
> (دالة `apply_residence` في القسم [٣]).

**التطوير التلقائي** — لما تفعّله، البوت بيشغّل خاصية اللعبة نفسها ويجدّدها
لوحده قبل ما تخلص بخمس دقايق.

**النجمة** جنب اسم كل حساب: رمادية = موقوف، خضرا = شغّال، حمرا = فيه مشكلة
والسبب مكتوب تحتيها.

## ٧. إضافة ميزة جديدة

كل حاجة اتبنت عشان الإضافة تبقى في مكانين بس:

1. **في القسم [٣]** — ضيف الدالة اللي بتنده على اللعبة جوه `GameClient`:

```python
def collect_bonus(self):
    status, body = self.post("/bonus/collect", {})
    if status in (200, 201):
        return body
    raise GameError(_message_of(body) or "المكافأة مش متاحة")
```

2. **في القسم [٤]** — ضيف منفّذ المهمة وسجّله في `HANDLERS`:

```python
def task_bonus(account, payload):
    client_for(account).collect_bonus()
    return "استلم المكافأة"

HANDLERS["bonus"] = task_bonus
```

وخلاص — الأمر بقى شغّال فردي وجماعي، ومعاه إعادة المحاولة والتسجيل في اللوج.
لو عايزه يشتغل لوحده كل فترة، ضيف سطر في `schedule_periodic()`.
ولو عايزله زرار في الواجهة، ضيفه في القسمين [٥] و[٦].

## ٨. لو حصلت مشكلة

**الصفحة بتقول خطأ في القاعدة** — غالباً استخدمت الرابط المباشر بدل الـ Session
pooler. راجع الخطوة الأولى. أو إن مشروع Supabase اتوقف من قلة الاستخدام —
افتح لوحة Supabase وشغّله تاني.

**كل الحسابات وقفت فجأة والخطأ "التوكن مرفوض"** — التوكنات بتنتهي. جدّدها من
`تعديل` في كل حساب.

**البروكسي مش رادّ** — جرّب `اختبار الاتصال` من النافذة. لو استخدمت `socks5`
اتأكد إن الصيغة صح: العنوان من غير `http://` قدامه.

**المهام واقفة في الطابور ومش بتتنفذ** — يبقى الكرون مش شغّال. افتح
`https://<خدمتك>.onrender.com/cron/tick?key=<CRON_SECRET>` من المتصفح
وشوف الرد إيه.

**السجل فاضي وكل حاجة واقفة** — دوس `تشغيل نبضة الآن` من فوق ولاحظ الرسالة.
